# Ontology V0.1 QA and Release-Readiness Report

Date: 2026-08-18  
Scope: ontology construction artifacts only; retrieval, ontology population, GraphRAG, and Graphiti are excluded.

## Result

V0.1 is suitable as an internally validated draft for continued ontology construction. It is **not ready for public
release** because namespace publication, licensing, independent legal review, and full OWL 2 DL reasoner gates remain
open.

The automated QA suite is implemented in `tests/ontology/` and reusable validation code is in
`src/legal_rag/ontology_validation/`. The suite parses artifacts, checks the policy-controlled import graph and XML
catalog, executes SHACL boundary validation, runs all mandatory CQ projections, and verifies identifier traceability.

Active modules are `MOD-SOURCE`, `MOD-OCCURRENCE`, `MOD-TEMPORAL`, `MOD-NORMATIVE`, and `MOD-CONSEQUENCE`. The root
imports every active module, each module declares only its direct local dependencies, and the local import graph is
acyclic.

## Automated Structural Gates

- Parse every root, module, shape, and fixture Turtle file.
- Match ontology IRIs, version IRIs, module files, and direct imports to `formalization_policy.yaml`.
- Resolve canonical and versioned local IRIs through `catalog-v001.xml` and verify mapped files exist.
- Reject the currently deferred cardinality, equivalence, disjointness, and SWRL constructs.
- Require readable labels and descriptions for local OWL terms and labels for controlled SKOS values.
- Verify that `lortc:validDuring` has no common domain that would create accidental classifications.
- Verify that the normative module supplies `PenaltyRule` ranges for earlier/later legal-change links.
- Resolve ontology and shape traceability IDs against the requirement, CQ, glossary, and modeling-decision registries.

These gates audit known modeling pitfalls, but they are not a substitute for an OWL 2 DL profile checker or DL
reasoner. Consistency and unsatisfiable-class checks remain a release gate until a suitable reasoner is run.

## Mandatory CQ Coverage

Every mandatory CQ has one manifest-owned SPARQL projection with reviewed columns and row expectations. A projection
returns modeled evidence and candidate structure; it does not silently make the legal decisions listed as deferred
output fields.

| CQ | Executable construction-stage projection | Semantic boundary |
| --- | --- | --- |
| `CQ-SOURCE-001` | Source provision path and supported component | Source authority remains a review responsibility |
| `CQ-EVIDENCE-001` | Assertion, exact span, chunk, file, provision | Evidence sufficiency requires review |
| `CQ-RULE-001` | Context-to-rule candidates | Condition satisfaction and final applicability deferred |
| `CQ-NEGATIVE-001` | Missing context dimensions | Remaining-rule determination deferred |
| `CQ-TEMPORAL-001` | Occurrence and rule validity data | Applicable/excluded versions deferred |
| `CQ-TEMPORAL-002` | Evidenced earlier/later change structure | Changed-field interpretation deferred |
| `CQ-APPLICABILITY-001` | Required subject, role, and vehicle context | No occurrence-level decision |
| `CQ-CONDITION-001` | Condition-expression tree and evidence | Condition truth deferred |
| `CQ-EXCEPTION-001` | General rule, exclusion citation, redirect | Legal priority remains reviewable |
| `CQ-ASSEMBLY-001` | Independently evidenced rule components | Nearby text is not assembled automatically |
| `CQ-PENALTY-001` | Monetary bounds, currency, and source | Missing money data is not zero |
| `CQ-CONSEQUENCE-001` | Consequence subtype, target, role, and source | Missing data is not proof of legal absence |
| `CQ-POINTS-001` | Point value, license target, role, and source | Role applicability remains explicit |
| `CQ-ADDITIONAL-001` | Additional sanction and target | Points are not reclassified as sanctions |
| `CQ-REMEDY-001` | Remedy, responsible role, target, condition, source | Form content alone does not prove a remedy |
| `CQ-COMPARISON-001` | Shared conduct and differing modeled dimensions | Similarity does not establish rule identity |

## Semantic Limitations

- Structural projections do not constitute a final legal-applicability decision.
- Condition satisfaction and legal classification require semantic analysis plus authoritative legal confirmation; an
  LLM may assist but must not be the sole acceptance gate.
- A missing validity end means unknown, not an infinite interval.
- A missing modeled consequence means unknown or absent from available evidence, not zero or legally absent.
- The same or similar conduct does not imply the same rule, amendment relationship, or legal identity.
- A vehicle owner is not automatically its driver or operator; roles are contextual assignments.
- Lexically similar text does not prove amendment, replacement, repeal, or equivalence.
- Text found in an attachment or form does not by itself establish a normative `RemedialMeasure`.

## Open Release Gates

- Register and verify the proposed `w3id.org` redirect and publish namespace documentation.
- Select and record repository and ontology licenses before public distribution.
- Obtain independent legal-domain review; current artifacts assert only project-owner acceptance for draft work.
- Complete pending reviews for legal effective dates, change types, legal identity, condition grouping, and consequence
  classification.
- Run an OWL 2 DL profile check and a DL reasoner for consistency and unintended unsatisfiable classes.
- Review external reuse mappings and attributions before asserting alignments or importing external ontologies.

Passing the automated suite means the versioned construction artifacts are internally coherent against the current
policy and fixtures. It does not mean the ontology is legally certified or publicly released.
